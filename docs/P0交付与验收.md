## 交付范围

| 项目 | 实现 | 验收边界 |
|---|---|---|
| Agent Run | 政策问答/解读/合规、公告同步与 SSE/修订/重新核查、会议、舆情及工具调用统一运行记录 | 保存 run/trace/user/session、计划、父子步骤、模型/Prompt hash、证据、耗时和 usage |
| 混合检索 | 中文 bigram BM25Plus(delta=0)、Dense、RRF、远端/本地 CrossEncoder 和显式词法降级 | hash Dense 与词法重排仅用于离线回归，不冒充语义检索 |
| 政策时效 | 发布/生效/失效日期、地区、行业、发布机构、名称及最新可用版本过滤 | 失效日期为排他上界；地区为精确地区或“全国”，不自动推断行政层级 |
| Golden Dataset | `evals/datasets/`，20 政策问答、10 公告事实映射、8 会议用例 | 合成工程集，非真实政策准确率或完整公告生成质量验收 |
| Registry | 6 个工具、3 个 Skill，JSON Schema、权限、版本、审计、超时、受限并发及显式瞬时错误重试 | 写工具仅进程内幂等，超时线程不能强制终止，禁止重试未知写入结果 |
| 公告审核 | 原文定位的事实证据、正文/输入/证据指纹、独立审批、重新核查使历史审批失效、可信身份发布 | 作者不能自审；无作者、无来源、核查遗漏或证据过期均阻断发布 |
| 容量验证 | 真实 HTTP 1/50/500 并发突发、2 秒/30 秒阈值、P50/P95/P99/吞吐/错误率及客户端/服务端峰值 | Python 单进程、隔离 SQLite、合成数据、离线模型，不包含生产全链路 |

Java 网关为 `/api/agent/**` 增加代理，并用服务端登录信息覆盖用户/权限/内部 Token/Trace 头，丢弃客户端伪造值。
管理端新增 `/admin/draft-reviews`，用户工作台展示来源、审批记录与重新核查操作。

## 关键接口

- `GET /api/agent/registry`：工具和 Skill 协议。
- `POST /api/agent/tools/{name}/invoke`：`{"input": {...}, "idempotencyKey": "..."}`，返回 `output` 与 `runId`。
- `GET /api/agent/runs`、`GET /api/agent/runs/{run_id}`：管理员审计或本人运行详情。
- `GET /api/drafts?status=审阅&limit=20&offset=0`：可信审核员列表。
- `POST /api/drafts/{id}/verify`：重新核查并追加审批失效记录。
- `POST /api/drafts/{id}/review`：`{"decision":"approve|reject","comment":"..."}`。
- `POST /api/drafts/{id}/status`：草稿 -> 审阅 -> 发布，发布需有效独立审批与 `draft:write`。

Registry 工具：`search_policy`、`retrieve_materials`、`verify_facts`、`extract_meeting_items`、
`generate_announcement`、`export_word_document`。未虚构待办工具 `create_follow_up_task`。

## 部署

先备份数据库，在隔离预生产验证，再执行迁移。此任务没有对业务数据库执行升级。

```powershell
pip install -r requirements.txt
python -m alembic upgrade head
```

head 为 `8f1_agent_p0`，新增 `agent_run`、`draft_evidence`、`draft_review` 和政策有效期/地区/版本字段。
`create_all` 不能为既有表补列，不能代替 Alembic。head 检查和 PostgreSQL 离线 SQL 生成均已验证。
历史稿件须通过可信身份重新核查并重新送审，不能迁移为默认已审批。

Java 与 Python 的 `AI_INTERNAL_TOKEN` 必须一致且足够强；Python 服务应仅开放给可信内网网关。
语义 Reranker 配置见 `.env.example`：`RERANK_URL`/`RERANK_API_KEY`/`RERANK_MODEL`，
或显式设置 `RERANK_LOCAL_MODEL`。本地 CrossEncoder 需另行安装匹配的 `sentence-transformers` 和模型，
本任务没有自动下载模型或调用付费接口。

## 审计与已知限制

- 成功业务函数在返回前自行提交业务写入；审计复用请求 Session，并在最后提交。不要把未提交的业务事务带到装饰器外部。
- 当前 Run 在结束时落库；运行中进度通过 SSE 和日志呈现，进程被强制终止时不保证留下完整 Run。
- 对业务文本做有界快照与常见秘密键脱敏，不等于全面 PII 脱敏。生产文本和审核证据不得进入公开 Golden Dataset。
- 模型 usage 缺失时标明不完整，未知费用为 `null`，不捏造 Token/成本。
- 事实映射要求可定位的完整原文，不接受散落数字拼接。改写无法定位时保守拒绝，补充来源后重新核查；规则抽取不是完整语义事实识别证明。
- 混合检索仍对数据库候选做进程内评分，需用真实语料规模验证资源成本。跨租户治理、持续稳态容量、故障演练和高可用 SLA 另行验收。
- 写工具的幂等状态不会跨重启或多实例共享，上线前需持久化幂等表或 Redis 原子状态协议。

保留期默认 30 天，先 dry run，再经审批删除已结束的 Run；此命令不删除公告证据和审批记录：

```powershell
python -m app.agent.maintenance --days 30
python -m app.agent.maintenance --days 30 --apply
```
