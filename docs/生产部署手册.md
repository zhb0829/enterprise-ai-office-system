# 企业AI智能办公系统 — 生产部署手册

> 适用版本：Java/前端应用仓库 + 独立 Python AI 仓库 + deploy 编排配置
> 目标环境：国内云服务器（单机 docker-compose），HTTP 内网运行（HTTPS/域名后置，Caddy 可预留）

## 一、前置条件

| 项 | 要求 |
|---|---|
| 服务器 | Linux x86_64，≥4C8G，磁盘 ≥80G（文件存储 + 数据库 + 镜像） |
| 软件 | Docker ≥ 24 + Docker Compose v2 |
| 网络 | 可拉取 Docker Hub 镜像（或已配置国内加速） |
| 仓库 | Java/前端仓库与 Python AI 仓库分别使用 main 分支 |

## 二、首次部署（12 步）

```bash
# 1. 克隆 Java/前端仓库；Python 仓库单独维护并构建 ai-service 镜像
git clone https://github.com/zhb0829/enterprise-ai-office-system.git
cd enterprise-ai-office-system

# 2. 进入部署目录并生成环境配置
cd deploy
cp .env.example .env

# 3. 生成随机密钥（只显示到终端，不要写入 Git）
echo "JWT_SECRET=$(openssl rand -hex 32)"
echo "AI_INTERNAL_TOKEN=$(openssl rand -hex 16)"
echo "OPINION_INTERNAL_TOKEN=$(openssl rand -hex 16)"
echo "MEETING_INTERNAL_TOKEN=$(openssl rand -hex 16)"
echo "POSTGRES_PASSWORD=$(openssl rand -base64 24)"
echo "GRAFANA_ADMIN_PASSWORD=$(openssl rand -base64 24)"

# 4. 编辑 .env：粘贴上述值，并填写 LLM/Embedding Key、正式域名 CORS、ACR 地址
vi .env

# 5. 静态校验配置（此处不启动服务，也不输出展开后的密钥值）
docker compose config --quiet

# 6. 纯镜像模式（推荐）：先登录私有镜像仓库
docker login <ACR_REGISTRY>
docker compose pull
docker compose up -d

# 7. 无 registry 时的本地构建模式：
#    Python ai-service 镜像需先在独立 Python 仓库构建并导入本机；
#    Java/前端/网关使用本地构建叠加层：
#    docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build

# 8. 查看首启随机管理员密码（不使用默认密码）
docker logs eaos-admin-server 2>&1 | grep "初始密码"

# 9. 基础验证
curl http://localhost/api/health                 # Java 网关 → 200
curl http://localhost/api/notifications/unread-count   # → 401（未认证，正常）

# 10. 浏览器访问
#     用户工作台:  http://<服务器IP>/
#     管理控制台:  http://<服务器IP>/admin/

# 11. 使用随机密码登录 admin，系统会强制要求修改密码
# 12. （管理端）系统管理 → 用户管理：创建业务账号、分配角色
```

## 三、.env 必填项说明

> admin-server 启动时会 fail-fast 校验密钥：空值、`change-me` 占位、历史默认值都会拒绝启动。
> `.env` 只保留在部署机或 Secret 管理系统中，禁止提交到 Git。所有真实值均由部署人员注入。

| 变量 | 说明 | 生成建议 |
|---|---|---|
| `POSTGRES_PASSWORD` | 数据库密码 | `openssl rand -base64 24` |
| `JWT_SECRET` | JWT 签名密钥（≥32 字符） | `openssl rand -hex 32` |
| `AI_INTERNAL_TOKEN` | Java↔Python 服务间令牌（≥16） | `openssl rand -hex 16` |
| `OPINION_INTERNAL_TOKEN` | 舆情模块服务间令牌（≥16） | `openssl rand -hex 16` |
| `MEETING_INTERNAL_TOKEN` | 会议模块服务间令牌（≥16） | `openssl rand -hex 16` |
| `CORS_ALLOWED_ORIGINS` | 前端来源（逗号分隔） | 换成正式域名 |
| `LLM_API_KEY` | DeepSeek/OpenAI 兼容密钥 | LLM 供应商控制台 |
| `EMBEDDING_API_KEY` | 向量化服务密钥 | 同上 |
| `GRAFANA_ADMIN_PASSWORD` | Grafana 管理密码 | 自定义 |
| `GRAFANA_ALERT_EMAILS` | 告警收件邮箱 | 运维邮箱 |
| `ACR_REGISTRY` | 含命名空间的镜像仓库地址 | 例如 `registry.cn-hangzhou.aliyuncs.com/eaos` |

### 3.1 一次性生成真值

在 Linux 部署机的 `deploy` 目录执行以下命令，将输出值粘贴到 `.env` 对应变量：

```bash
echo "JWT_SECRET=$(openssl rand -hex 32)"
echo "AI_INTERNAL_TOKEN=$(openssl rand -hex 16)"
echo "OPINION_INTERNAL_TOKEN=$(openssl rand -hex 16)"
echo "MEETING_INTERNAL_TOKEN=$(openssl rand -hex 16)"
echo "POSTGRES_PASSWORD=$(openssl rand -base64 24)"
echo "GRAFANA_ADMIN_PASSWORD=$(openssl rand -base64 24)"
```

约束：`JWT_SECRET` 至少 32 个字符，三个内部令牌至少 16 个字符；任何空值、`change-me` 或历史默认值都会被 Java `SecretProperties` 与 Python `Settings` 拒绝。

## 四、域名、TLS 与 CORS

1. 为用户端和管理端域名创建 DNS A/AAAA 记录，指向服务器公网 IP，例如 `office.example.com` 与 `admin.example.com`。
2. 在云 LB、Caddy 或其他反向代理层终止 TLS，对外提供 HTTPS 443；反向代理回源到本机 `GATEWAY_PORT`（默认 80）。
3. 网关容器不保存证书、不暴露 Python 端口；数据库、Grafana、Prometheus、Loki 和 ai-service 只允许内网或防火墙白名单访问。
4. 在 `.env` 中将 `CORS_ALLOWED_ORIGINS` 设置为浏览器实际来源，多个来源用英文逗号分隔，必须与地址栏中的协议、域名和端口精确一致，例如：

```dotenv
CORS_ALLOWED_ORIGINS=https://office.example.com,https://admin.example.com
```

配置完成后，用浏览器分别打开两个 HTTPS 域名，确认页面、登录、API 请求和跨域预检均正常。

## 五、服务拓扑

```
用户/浏览器
   │ HTTPS :443
   ▼
云 LB / Caddy（TLS 终止，回源 GATEWAY_PORT=80）
   │ HTTP 内网
   ▼
gateway (nginx)
   ├── /            → frontend        (用户工作台, Vue3)
   ├── /admin/      → frontend-admin  (管理控制台, Vue3, base=/admin/)
   ├── /api/        → admin-server    (Spring Boot 3, 认证/网关/管理业务, :8080)
   │                     └── /internal 反代 → ai-service (FastAPI, :8000)
   └── /api/files/** → admin-server    (Java 鉴权后代理读取受控文件)

数据面:  db (pgvector/pg16) ←─ Java Flyway + Python Alembic（每张表单一所有者）
         file-storage volume  (Java /data/storage/java + Python /data/storage/{uploads,exports})
观测面:  prometheus / grafana(:3000) / loki / promtail / node-exporter
```

浏览器禁止直连 `ai-service`，也不存在生产 `/static/` 下载入口。Python Worker 的情报、舆情、会议结果通过内部 API 回写 Java；文件下载统一使用 Java `/api/files/**` 完成认证、授权和路径校验。

## 六、观测与告警

- Grafana：`http://<IP>:3000`（账号 admin / `.env` 中的 `GRAFANA_ADMIN_PASSWORD`）
- 日志检索：Loki 数据源，按 `{container="eaos-admin-server"}` 过滤，日志行内含 `[traceId]`
- 全链路排障：浏览器 Network 复制响应头 `X-Trace-Id` → Grafana Explore 检索该 traceId，可同时命中 Java 与 Python 日志
- 内置告警（EAOS 文件夹）：服务下线、5xx 率、LLM P95、磁盘 >80%；SMTP 配置后自动邮件通知

## 七、联调与上线验收

### 7.1 基础服务

```bash
cd deploy
docker compose ps
curl -fsS http://localhost/api/health
curl -i http://localhost/api/notifications/unread-count  # 预期 HTTP 401
docker logs eaos-admin-server 2>&1 | grep "初始密码"
docker logs eaos-ai-service 2>&1 | grep -E "APP_ENV=production|token"
```

### 7.2 Python 内网健康与回调链路

```bash
# Python 健康检查不经公网网关，仅在容器内携带内部令牌访问
docker exec eaos-ai-service sh -lc \
  'curl -fsS -H "X-Internal-Token: $AI_INTERNAL_TOKEN" http://localhost:8000/internal/health'

# 查看 Worker 是否成功回写情报、舆情和会议结果
docker compose logs --since=10m ai-service | grep -E \
  "internal/intelligence|internal/opinion|internal/meeting"
docker compose logs --since=10m admin-server | grep -E \
  "intelligence|opinion|meeting|traceId"
```

实际业务联调至少覆盖：情报任务创建后 Python 回写 `/internal/intelligence`；舆情采集、分析和报告回调；会议任务的进度、成功和失败回调。每条链路均应能在 Java 与 Python 日志中用同一个 `traceId` 对上。

### 7.3 受控下载与观测

```bash
# 使用已登录用户获得的 JWT；将 <file-id> 替换为业务返回的文件标识
curl -I -H "Authorization: Bearer <JWT>" \
  http://localhost/api/files/<file-id>

# 未携带 JWT 应被拒绝；浏览器不能使用 /static/ 直接下载
curl -i http://localhost/api/files/<file-id>
curl -i http://localhost/static/<file-id>
```

受控下载应满足：已授权用户返回文件或业务定义的 404；未认证/无权限返回 401/403；`/static/` 不提供 Python 文件。打开 Grafana Explore，以容器标签筛选 Loki 日志，并用响应头 `X-Trace-Id` 查询同一请求，确认 Java/Python 日志可关联。

## 八、日常运维

```bash
docker compose ps                      # 服务状态
docker compose logs -f admin-server    # 跟日志
docker compose restart admin-server    # 重启单服务
docker compose pull && docker compose up -d   # ACR 开通后：拉镜像滚动升级
```

- **备份**：`pgdata` 与 `file-storage` 两个 volume 是唯一状态，建议每日快照
  （`docker run --rm -v eaos_pgdata:/data -v /backup:/backup alpine tar czf /backup/pgdata-$(date +%F).tgz /data`）
- **扩容注意**：单机 volume 架构下不可水平扩展 Java/Python 实例；多实例前须先切换文件存储为对象存储实现（接口已预留）

## 九、故障排查

| 现象 | 排查 |
|---|---|
| admin-server 起不来，日志有"密钥未配置，拒绝启动" | `.env` 缺少必填密钥，见第三节 |
| 登录提示"用户名或密码错误" | 首启密码见 `docker logs eaos-admin-server | grep 初始密码` |
| 页面空白/资源 404 | 清浏览器缓存后强刷；确认访问的是 `/` 或 `/admin/` 前缀 |
| AI 功能报"AI 服务暂时不可用" | `docker compose logs ai-service`；检查 `LLM_API_KEY` |
| 上传失败 413 | nginx `client_max_body_size 500m` 已配置，检查前置 LB 是否覆盖 |
