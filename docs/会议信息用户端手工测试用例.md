# 会议信息用户端手工测试用例

## 测试环境

- 用户端：`http://localhost:5175/workspace/meeting`
- Java 网关：`http://localhost:8080`
- Python AI 服务：`http://localhost:8000`（解析、纪要生成、关联推荐依赖该服务）
- 测试日期：2026-08-30

## 测试数据准备

1. 准备以下测试文件：
   - 一份会议公开报道页面 URL（http/https，可正常访问）；
   - 一段会议录音转写文本（纯文本，长度不限，建议 ≥ 200 字）；
   - 一个 PPT 截图图片文件（PNG/JPG）；
   - 一份 PDF 或 Word 文档；
   - 一段音频文件（MP3/WAV，可选，用于验证上传通道）。
2. 使用一个已登录的用户端账号执行全部用例。

## 用例

| 编号 | 测试项 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| TC-MT-01 | 导航入口 | 登录用户端，点击顶部导航“会议信息”。 | 跳转到 `/workspace/meeting`，导航项高亮；页面标题为“会议公开信息”，右上角有“新建会议”按钮。 |
| TC-MT-02 | 新建窗口字段 | 点击“新建会议”。 | 表单仅含：会议名称（必填）、开始时间、结束时间；下方同一窗口内包含“公开资料链接”“转录文本”“上传文件”三个导入区。 |
| TC-MT-03 | 仅名称保存（无资料） | 只填会议名称（如“测试会议 A”），点击“保存会议”。 | 保存成功并跳转到该会议详情页；不弹出“是否立即生成纪要”的询问；详情页显示“尚未添加资料”。 |
| TC-MT-04 | 缺少名称校验 | 清空会议名称，点击“保存会议”。 | 提示“会议名称不能为空”，不发起请求，表单不关闭。 |
| TC-MT-05 | 链接导入 | 在新建窗口“公开资料链接”填入有效 URL 与标题，点击“保存会议”，确认弹窗中选择“确定”。 | 会议创建成功，链接资料出现在详情页资料列表且标记为“待解析”；随后自动发起整理，会议状态变为“整理中”并显示五步进度。 |
| TC-MT-06 | 转录文本导入 | 新建会议时在“转录文本”粘贴转写内容，填标题，保存并确认生成。 | 转录稿出现在资料列表（类型“转录稿”）；生成完成后纪要中体现转录内容要点。 |
| TC-MT-07 | 图片（PPT 截图）导入 | 新建会议时通过“上传文件”选择 1 张 PPT 截图，可同时多选其他文件，保存并确认生成。 | 待上传列表显示文件名与大小，可逐个“移除”；保存后资料类型为“图片”；解析结果由 Python 侧回写（视觉模型或 OCR 降级，在 parseResult 中标注）。 |
| TC-MT-08 | 文档/音频导入 | 上传一份 PDF（或 Word）与一段音频，保存。 | 资料类型分别为“文件”“音频”；音频上限 500MB、其他文件上限 100MB，超限时报错且不创建资料。 |
| TC-MT-09 | 保存后自动询问生成 | 带 ≥1 份资料保存且全部资料提交成功。 | 弹窗“会议与资料已保存，是否立即生成结构化会议纪要？”；选“确定”后发起整理；选“取消”则停在详情页，可稍后手动点“生成会议纪要”。 |
| TC-MT-10 | 单项资料失败不中断 | 在新建窗口填入一个无效链接（如 `abc`）+ 一份转录文本，保存。 | 链接校验失败被汇总提示（如“链接添加失败：…”），其余资料仍提交成功；保存流程不中断。 |
| TC-MT-11 | 整理进度与结果 | 发起整理后停留在详情页。 | 进度条按“采集补充报道 → 解析多模态资料 → 提炼会议要点 → 生成纪要与知识卡片 → 关联政策、竞品与历史会议”推进；完成后显示 Markdown 纪要、知识卡片（核心观点/决策事项/行动项/专家观点/关键数据）。 |
| TC-MT-12 | 关联信息列表 | 打开一份已完成整理的会议。 | 右侧栏依次显示“政策推荐”“竞品动态”“相关会议”三个区块；竞品动态条目含标题、相似度、摘要并可点击外链打开原文；无结果时显示“暂无达到阈值…”空态。 |
| TC-MT-13 | 重新整理 | 在详情页再补充一份资料，点击“重新整理”并确认。 | 会议回到“整理中”；完成后生成新版本纪要（v2+），版本下拉可切换历史版本，旧版本内容不变。 |
| TC-MT-14 | 导出 Word | 在详情页选择任一纪要版本，点击“导出 Word”。 | 下载 `.docx` 文件，文件名含会议名与版本号；标题/列表/加粗排版与页面一致。 |
| TC-MT-15 | 资料删除与上限 | 删除一份资料；向同一会议累计添加至 50 份后再添加。 | 删除需二次确认且立即从列表移除；达到 50 份后提示“单个会议最多添加 50 份资料”。 |
| TC-MT-16 | 重复资料去重 | 将同一链接或同一文件再次添加到同一会议。 | 提示“该资料链接已添加”或“该文件已上传，请勿重复提交”。 |
| TC-MT-17 | 列表筛选与状态 | 回到列表页，按关键词和状态（待整理/整理中/已完成）筛选。 | 列表按条件过滤；“资料”列计数与详情页一致；整理中的会议有轮询刷新，状态自动更新。 |
| TC-MT-18 | 通知 | 整理任务完成或失败后，查看顶部“通知”。 | 创建者收到站内通知（整理完成/失败及原因），未读数更新，可标记已读。 |
| TC-MT-19 | 响应式布局 | 窗口宽度分别调至约 760px、1050px、1440px。 | 表单三列 → 两列 → 单列正常折行，无横向滚动、无控件重叠。 |

## 通过标准

- TC-MT-01 至 TC-MT-14 为核心链路，必须全部通过。
- TC-MT-15 至 TC-MT-19 为边界与体验项，允许记录为已知问题后跟踪。
- 依赖 Python AI 服务的用例（TC-MT-05 至 TC-MT-14 中的解析/生成部分）在服务未启动时，仅验证到 Java 侧的提交与失败提示即可，标注“待 Python 服务可用后复测”。
- 任一用例失败时，记录浏览器控制台错误、请求 URL、响应状态码和复现步骤。
